# ADR-0002: Модель данных — три признака на каждый срез + дата первого появления

Дата: 05.11.2026
Статус: принята (подтверждена проверкой H-02)

## Контекст

Заказчик согласовал 7 состояний клиента: все переданы, впервые, уменьшается,
не меняется или растёт, повторное, хронический, новичок. Состояния сочетаются
(например, «хронический» и «уменьшается» одновременно), историю срезов хранить
требует ТЗ. Сравнивались два способа хранения: А) одно поле «категория»
у клиента; Б) три отдельных признака на каждый срез + дата первого появления.

## Решение

Храним по каждому клиенту в каждом срезе три отдельных признака
(модель Б, решение Р-02):

1. `dynamics_code` — изменение между срезами: NO_COMPARISON, ALL_TRANSFERRED,
   FIRST_APPEARED, DECREASING, FLAT_OR_GROWING, REAPPEARED;
2. `is_novice` — «новичок» (признак клиента: подключён менее 6 месяцев назад);
3. `is_chronic` — «хронический» (ситуация сохраняется: непереданные > 0, этап
   дальше «Выявлены», в предыдущем квартале непереданные были, обнулений не было).

Плюс `client.first_appearance_date` — дата первого появления клиента.
Срезы не перезаписываются (SN-01). Итоговая категория для показа выводится
приоритетом: Нет сравнения → Нет данных → Хронический → Новичок (при not>0) →
изменение. Поле категории в БД не хранится — выводится из трёх признаков.

## Обоснование (H-02, 05.11.2026)

- 18 из 18 допустимых сочетаний записываются без противоречий; модель А
  сворачивает 10 из 18 с потерей информации.
- Восстановление состояния на прошлые срезы только по сохранённым данным:
  модель Б 211/211, модель А 0.
- Совпадение с ручным расчётом: 86/86 (контрольная книга DS-02) и 187/187
  строк, 51/51 клиентов (ручная разметка 50 клиентов) — критерий «≥ 49 из 50»
  выполнен; единственное расхождение (флаг «новичок» при not=0) — конвенция
  отображения, зафиксирована в карточке H-02.
- Время пересчёта 0,02 с на срез 3 000 строк (требование H-04 — до 60 с).
