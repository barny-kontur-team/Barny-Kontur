# Путь данных: Excel → импорт → база → динамика → API → экран

## 1. Источники и ключ

Импорт в **текущем backend** ожидает тестовые Excel-шаблоны из `data/test/h02/` и `data/templates/`, где ключ — столбец `Код КЦР`. Сначала загрузить клиентов, потом срезы. Это **не** равнозначно сырым обезличенным файлам заказчика H-01, в которых код КЦР мог отсутствовать: для них нужна отдельная трансформация/сопоставление по обезличенному ID.

## 2. Клиенты

`POST /api/imports/clients` → `importer.validation.parse_workbook(..., "clients")`: обязательны `Код КЦР`, `ИНН`, `Название организации`; доп. поля: `КПП`, `Тип клиента`, `Дата подключения`, `Не включать в работу`. Отсутствие обязательного, повторы в файле = `422`; существующий код в БД = `409`. Затем одна транзакция добавляет `client` и `import_batch` (успешный пакет).

## 3. Срезы

`POST /api/imports/snapshots` — multipart: файл + `reporting_period` + `snapshot_date`. Внутри Excel обязательны столбцы `Код КЦР`, `Документов всего`, `Не передано документов`; `Документов всего` может быть пустым **только** для клиента, у которого уже существует срез в том же периоде. Проверки: числовые целые неотрицательные значения, `missing <= total` (когда total задан), отсутствие неизвестных КЦР, дубликатов кода внутри файла. Любая ошибка → `422` и **весь файл отклонён**; повтор пары клиент/квартал/дата в БД → `409`.

При успехе: `import_batch` → по строке `document_snapshot` со ссылками на `client` и `import_batch`. История не стирается. Сохраняются исходные `total_documents` (возможно NULL) и `missing_documents`.

## 4. Пересчёт модели Б

В той же операции импорта `dynamics.service.recalculate_client` читает **всю историю** затронутого клиента в порядке дат и считает `dynamics_code`, независимые `is_novice`, `is_chronic`, `missing_percent` по опорному total. Пересчитываемые значения могут обновляться и у исторических записей; исходные числа и даты срезов **не меняются**. У клиента обновляется `first_appearance_date`.

Новичок: подключение менее шести календарных месяцев назад, даже при нуле непереданных. В API метка видна только если `is_novice = true` **и** `missing_documents > 0`. Подробнее — [ADR-0002](adr/0002-model-dannyh-b.md).

## 5. API и будущий экран

`GET /api/clients/{client_id}/dynamics` возвращает код клиента, первую дату появления и массив `history` со срезами, рассчитанными признаками и итоговой отображаемой категорией. **Сейчас данные доступны по API/Swagger; реального экрана, читающего этот API, в архиве нет.** Макеты/интерфейс должны использовать `history`, `category`, `show_novice_badge` без повторного вычисления модели на фронтенде.

## 6. Ограничения/риски

- История этапов работы на дату среза отсутствует → флаг `is_chronic` при пересчёте может зависеть от текущего этапа.
- Не реализованы частичный импорт H-01, звонки/претензии, UI и авторизация; эти ветки не включать в демонстрацию как работающие.
- Сырые Excel заказчика с пустым КЦР не подходят напрямую для текущего импортера.
