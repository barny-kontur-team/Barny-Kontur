# scripts/h03 — прогон H-03 / H-05

Проверка ИИ-помощника на 30 контрольных вопросах из протокола от 16.11.2026
(15 сводок, 12 выборок словами, 3 «нет данных»). Вопросы и эталоны
зафиксированы до запуска — подогнать ответы нельзя.

## Что проверяем

- **H-03** — ИИ с доступом к данным полезен и не выдумывает.
- **H-05** — сравнение моделей на одном наборе.

Две функции помощника (см. `backend/ai/`):

1. `summary.py` — сводка по клиенту: факты считает код, модель пересказывает.
2. `search.py` — выборка словами: модель подбирает условия фильтра,
   клиентов отбирает код (`schemas.apply_filter`). Модель не видит список
   клиентов и не может назвать лишний код.

## Данные

- `data/test/h02/01_Корректные_импорты` — клиенты и срезы S001–S006 (15 клиентов).
- `scripts/h03/fixture.json` — этапы и звонки из протокола (раздел 1.1–1.2).
- `scripts/h03/questions.json` — 30 вопросов и эталоны.
- `scripts/h03/filters_reference.json` — эталонные условия 12 запросов блока Б.

Правила динамики не переписаны: берутся готовые из `backend/dynamics/features.py`
(после переноса H-02 в сервис).

## Запуск

```bash
# из корня репозитория
python -m pip install -r backend/requirements-dev.txt

# 1. Проверить загрузку данных (без моделей)
python scripts/h03/run_questions.py --check-data

# 2. Проверить, что эталонные условия дают эталонные коды
python scripts/h03/run_questions.py --check-filters

# 3. Полный прогон трёх моделей
python scripts/h03/run_questions.py --models deepseek-flash,qwen3.5:2b,gemma4:e2b

# 4. Быстрая проверка одной модели и одного блока
python scripts/h03/run_questions.py --models qwen3.5:2b --blocks B --limit 2

# 5. Таблица для ручной разметки блока А
python scripts/h03/build_scoring.py
# → scripts/h03/out/h03_scoring.xlsx
```

## Ручная разметка блока А

`build_scoring.py` собирает книгу Excel по результатам прогона: лист на
каждую модель, по строке на сводку. В строке — эталон, ответ модели,
контрольные значения последнего среза и чек-лист из четырёх пунктов
(звонки, обещание, динамика, итог). Колонка «Полный» и сводка по моделям
считаются формулами. Разметка делается по чек-листу 2.2 протокола.

Отметки хранятся в `scoring.json` (модель → вопрос → четыре пункта, число
факт-ошибок, комментарий). Если файла нет, книга собирается с пустыми
колонками для ручного заполнения. Текущая разметка — в репозитории.

Для DeepSeek нужен ключ в окружении:

```bash
export DEEPSEEK_API_KEY=...      # Linux/macOS
$env:DEEPSEEK_API_KEY = "..."    # PowerShell
```

Для локальных моделей должен быть запущен Ollama (`ollama serve`,
API на `127.0.0.1:11434`). Используются только уже скачанные модели.

## Результаты

Пишутся в `scripts/h03/out/` (в git не попадают):

| Файл | Что внутри |
|---|---|
| `<модель>/answers.jsonl` | каждый ответ дословно, фильтр, коды, время |
| `<модель>/report.md` | вопрос, ответ, эталон, автопроверка |
| `summary.md` | сводка по моделям |
| `summary.json` | те же данные машинно-читаемо |

Автопроверка:

- блок Б — множество кодов от кода сравнивается с эталоном;
- блок В — есть ли «нет данных» и нет ли выдуманных контактов/сумм;
- блок А — только кандидаты в факт-ошибки (числа вне фактов). Полноту
  оценивает человек по чек-листу 2.2 протокола.

## Замечания

- Формулировки блока Б приведены к принятой терминологии: «непереданные
  документы» вместо запрещённого слова. Смысл фильтров не изменён.
- «Давно не звонили» трактуется как в протоколе (О-3): звонок раньше
  01.10.2026 или звонков не было. Соглашение передаётся всем моделям одинаково.
- Локальные модели 2B — это проверка «хватает ли маленькой модели», а не
  сравнение «кто умнее». Результат блока Б у них ожидаемо слабее.
